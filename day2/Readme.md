# Day 02 – Git & GitHub

## Overview

On Day 2 of my #100DaysOfLearning journey, I learned the fundamentals of **Git and GitHub** and how they are used for version control and collaboration in software development.

## What I Learned

### 1. Git Setup

* Installed and configured Git.
* Set up GitHub for version control.
* Generated an **SSH key** and configured it for GitHub authentication.

### 2. GitHub Repository

* Created a new repository on GitHub.
* Connected my local project with the GitHub repository.
* Pushed my **Day 1 project** to GitHub.

### 3. Basic Git Operations

Learned and practiced the basic Git workflow:

* `git add` – Stage changes
* `git commit` – Save changes to the local repository
* `git push` – Upload local changes to GitHub
* `git pull` – Get the latest changes from the remote repository
* `git merge` – Combine changes from different branches

### 4. Branching

Learned how branches are used to work on different features or changes without directly affecting the main branch.

### 5. Merge Conflicts

Learned what **merge conflicts** are and how they occur when Git cannot automatically combine changes.

I also learned the basic process of identifying the conflicting changes, resolving them manually, and completing the merge.

## Practical Work

During the session, I:

1. Set up Git and GitHub.
2. Generated and configured my SSH key.
3. Created a GitHub repository.
4. Connected my local project to the repository.
5. Pushed my Day 1 menu page project to GitHub.
6. Practiced Git operations such as push, pull, and merge.
7. Worked with branches.
8. Learned how to resolve merge conflicts.

## Key Takeaway

Today I learned that Git is more than just a tool for uploading code. It helps developers **track changes, manage different versions of a project, work with branches, and collaborate with others**.
